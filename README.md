# Генератор актів і звітів

Локальний Windows-застосунок для імпорту Excel-книги, вибору аптечної мережі та варіанта ЛІК/ДД, перегляду акта й звіту з викладки та збереження одного Excel-файлу з двома аркушами.

## Запуск із Python

1. Встановіть Python 3.11 або новіший із підтримкою `tkinter`.
2. У каталозі застосунку виконайте:

   ```powershell
   py -m pip install -r requirements.txt
   py app.py
   ```

3. Завантажте книгу Excel зі структурою аналізованого шаблону, виберіть мережу й тип ЛІК/ДД, натисніть **Попередній перегляд**, перевірте обидва аркуші та збережіть файл.

Імпортовані книги зберігаються у локальній SQLite-базі:

- Windows: `%LOCALAPPDATA%\ActsReports\imports.sqlite3`
- Linux/macOS: `$XDG_DATA_HOME/ActsReports/imports.sqlite3` або `~/.local/share/ActsReports/imports.sqlite3`

## Поточні межі MVP

- Підтримуються `.xlsx` і `.xlsm` як вхід; вихід — `.xlsx`.
- Для запобігання хибним документам у списку вибору доступна мережа, на яку відфільтрований `PIVOT!B5` завантаженої книги. Щоб сформувати документи для іншої мережі, спершу потрібно відфільтрувати/оновити `PIVOT` у вихідному Excel і завантажити книгу повторно. Застосунок не оновлює Excel Data Model або зведені таблиці.
- Вихідні клітинки копіюються зі збережених результатів формул у завантаженій книзі, як статичні значення. Якщо Excel не перерахував книгу перед збереженням, збережені результати можуть бути застарілими.
- Попередній перегляд показує табличний вміст аркушів. Оформлення, об'єднані клітинки й друкована верстка вихідного шаблону ще не переносяться; поточний експорт застосовує базове форматування.
- Вихідний шаблон містить зовнішні підключення та формули, для яких потрібна окрема перевірка бізнес-логіки. MVP не підключається до баз даних і не перераховує розрахунки з нуля.

Перед використанням документів як фінальних необхідно звірити підсумки з актуальною книгою, а наступним етапом розробки має бути повне перенесення розрахунків у Python і відтворення верстки аркушів.
